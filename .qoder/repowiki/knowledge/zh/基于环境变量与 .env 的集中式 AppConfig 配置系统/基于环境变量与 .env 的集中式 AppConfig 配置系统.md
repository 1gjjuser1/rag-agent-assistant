## 1. 使用的系统与方案

本项目采用**纯 Python + 环境变量**的轻量级配置方案，核心由 `config.py` 中的 `AppConfig` dataclass 统一承载所有可调参数。配置加载依赖 `python-dotenv`（`load_dotenv()`）在模块导入时自动从项目根目录的 `.env` 文件加载键值对，再通过 `os.getenv` 读取；未设置时使用内置默认值。该方案没有引入 Pydantic Settings、YAML/JSON 配置文件或外部配置中心。

此外，部分模块也直接通过 `os.getenv` 读取自身所需的环境变量：
- `llm_client.py` 读取 DashScope 相关密钥与模型名（`DASHSCOPE_API_KEY`、`DASHSCOPE_CHAT_MODEL`、`DASHSCOPE_EMBEDDING_MODEL`、`DASHSCOPE_BASE_URL`、`DASHSCOPE_ENABLE_THINKING`）。
- `api.py` 读取 `API_AUTH_TOKEN` 用于可选的 Bearer Token 鉴权。
- `app.py` 读取 `LOGO_PATH` 覆盖 Streamlit 页面 Logo。
- `react_agent.py` 读取 Open-Meteo 的地理编码与天气接口 URL。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `config.py` | 集中定义 `AppConfig` dataclass 及 `from_env()` 构建器，提供 `_env_str/_env_int/_env_float/_env_bool/_clamp/_resolve_path` 等类型安全的读取辅助函数 |
| `llm_client.py` | 读取 DashScope API Key、模型名、base_url 等 LLM 运行时配置 |
| `api.py` | 读取 `API_AUTH_TOKEN`，实现可选鉴权 |
| `app.py` | 读取 `LOGO_PATH`，并通过 `AppConfig.from_env()` 构造 RAGPipeline |
| `.env.example` | 环境变量模板（示例文件，实际部署时复制为 `.env`） |
| `pyproject.toml` | 仅包含 pytest/ruff/mypy 工具配置，不包含应用运行配置 |

## 3. 架构与设计约定

- **单一配置入口**：`AppConfig.from_env(data_dir=None)` 是创建 RAGPipeline / ReActAgent 时的唯一配置来源。它返回一个 `frozen=True` 的 dataclass 实例，防止运行中被意外修改。
- **分层默认值**：每个字段都有明确的默认值（如 `CHUNK_SIZE=500`、`RETRIEVAL_TOP_K=5`、`RETRIEVAL_MMR_LAMBDA=0.7`、`AGENT_MAX_STEPS=5`），环境变量仅用于覆盖。
- **类型安全读取**：通过 `_env_int`、`_env_float`、`_env_bool` 包装 `os.getenv`，在解析失败时回退到默认值，避免启动期崩溃。
- **路径解析**：`_resolve_path` 支持绝对路径与相对路径（相对于 `PROJECT_ROOT/data`），`data_dir` 可被测试临时覆盖。
- **边界约束**：`EMBEDDING_BATCH_SIZE` 使用 `_clamp(value, 1, 20)` 限制在 1~20 之间，原因是 DashScope Embedding 接口单次最多 20 条。
- **模块内独立 env 读取**：非 AppConfig 管理的配置（如 `API_AUTH_TOKEN`、`LOGO_PATH`、DashScope 密钥、Open-Meteo URL）在各模块顶部直接 `os.getenv` 读取，不经过 `AppConfig`。
- **dotenv 加载时机**：`config.py` 和 `llm_client.py` 均在模块导入时调用 `load_dotenv()`，因此只要这两个模块先于业务逻辑导入，`.env` 中的变量就可用。

## 4. 约定与约束

- **所有可调参数必须通过环境变量覆盖**：`config.py` 注释明确说明“所有配置项同时支持环境变量覆盖”，且阶段 A 的目标就是让切分、检索、重排等行为可配置且可复现。
- **数据目录结构固定**：`data_dir` 下默认存放 `chroma/` 向量库与 `kb.sqlite3` 元数据库，路径可通过 `CHROMA_DIR`、`KB_DB_PATH` 环境变量覆盖。
- **布尔型环境变量取值约定**：仅当值为 `1`、`true`、`yes`、`on`（不区分大小写）时才视为真，其余均视为假。
- **缺失环境变量即使用默认值**：任何未设置的变量都会回退到代码中硬编码的默认值，不会抛出异常。
- **生产环境建议**：`api.py` 注释指出未配置 `API_AUTH_TOKEN` 时接口开放访问，“仅建议本机/内网调试”，意味着生产部署应设置该令牌。
- **无配置文件格式**：项目中不存在 YAML/JSON/TOML 形式的运行时配置文件，所有运行时参数均通过环境变量注入。
- **测试隔离**：`AppConfig.from_env(data_dir=...)` 允许传入临时目录以隔离测试数据，配合 tests 下的 pytest fixture 使用。
