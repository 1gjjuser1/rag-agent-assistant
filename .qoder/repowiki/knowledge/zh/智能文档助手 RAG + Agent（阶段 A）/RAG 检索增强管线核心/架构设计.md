模块以 `rag_pipeline.py` 中的 `RAGPipeline` 为统一门面，按职责拆分为四个协作层：
- 配置层 `config.py`：通过 `AppConfig` dataclass 集中读取环境变量（`CHUNK_SIZE`、`RETRIEVAL_TOP_K`、`CHROMA_DIR` 等），所有可调参数冻结不可变。
- 存储层 `store.py`：基于 SQLite（WAL + busy_timeout）维护 `kbs / documents / document_versions / chunks / meta` 五张表，提供知识库、文档版本历史、片段持久化及元数据键值存取；写操作用 `RLock` 串行化，读连接独立打开。
- 向量化层 `vector_store.py`：封装 Chroma `PersistentClient`，每个知识库一个 collection（命名 `kb_<kb_id>`，cosine 空间），提供批量 upsert、条件删除、相似度查询、取回原始向量（供 MMR 使用）。
- 解析与切分层 `ingestion.py`：`DocumentParser` 按后缀路由到 PyMuPDF/pypdf/docx/txt 加载，PDF 逐页质量评估后对乱码/扫描件走本地 RapidOCR；`split_documents` 用 `RecursiveCharacterTextSplitter` 按段落/句子边界切分；`build_chunk_metadata` 统一注入 source/page/paragraph 等引用元数据。
依赖方向单向：`RAGPipeline` → `store` + `vector_store` + `ingestion` + `utils.retrieval`（BM25/MMR/RRF），并通过 `LLMClient` Protocol 解耦 LLM 厂商（默认 `DashScopeClient`）。索引重建由 `_current_index_config` 生成的签名（chunk_size/overlap/embedding_model/parser_version）与 `meta.index_config_version` 比较触发，配合 `indexed_sha` 实现增量去重。
